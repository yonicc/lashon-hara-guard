# ארכיטקטורה סופית — גרסה 1 (מימוש מנוע)

מעמד: ארכיטקטורת מימוש שאומצה להתחלת בניית המנוע לפי הוראת המשתמש (2026-10-26).
״סופית״ כאן פירושו: בסיס המימוש הנוכחי. אין כאן פסק הלכה או חוות דעת משפטית, ואין כלל מאושר.
החלטות מוצר פתוחות (עצירה קשיחה, מדיניות כשל, מאשרי כללים) נשארות ב-[06-decisions](06-decisions.md).

## עקרונות מחייבים למימוש

1. **הפרדת אחריות:** מודל מחלץ עובדות מוצעות וראיות; קוד מעריך כללים. המודל לא מריץ קוד, לא משנה כללים ולא מספק פסק.
2. **לוגיקה תלת־ערכית:** כל תנאי מוערך ל־`true` / `false` / `unknown`. `unknown` אינו `false`. עובדה חסרה או שנויה במחלוקת חוסמת הכרעה בכלל התלוי בה.
3. **שער סטטוס סקירה:** רק כלל `approved` רשאי להפיק ממצא. כלל `draft` / `source_verified` / `expert_reviewed` מפיק לכל היותר `draftObservation` פנימי לצורכי פיתוח ובדיקה, ואינו מוצג כהכרעה.
4. **מוצא ומהימנות עובדות:** לכל עובדה provenance, scope ומועד. עובדה רגישה ומתמשכת (קשר משפחתי, זהות אדם) נעשית ידועה רק מאישור משתמש מפורש. חילוץ מודל או תוכן הודעה נכנסת יכולים להציע עובדה כמועמדת בלבד.
5. **תקציב שאלות:** ברירת מחדל — לכל היותר שאלה אחת להודעה (ניתן להגדרה). בוחרים את השאלה לפי מספר הכללים שהיא משחררת, חומרתם ועדיפות קבועה בקטלוג העובדות. שאלות אינן מופיעות כשהתשובה לא תשנה תוצאה.
6. **בקרה כפולה כחוזה:** ה־Extractor רשאי לצרף `directAssessment`. פער מהותי בין הערכה ישירה לתוצאת המנוע מסומן `disagreement` ומוריד את התוצאה ל״ספק / לבדיקה״. המנוע עצמו אינו תלוי בשדה זה.
7. **קונטקסט מקומי בלבד:** אין ארכוב הודעות ב־brain-mcp. תוכן וקשרים נשארים מקומיים; לענן נשלח מינימום נחוץ, ורק אחרי מדיניות ואישור.
8. **ביטול תוצאות:** מפתח מטמון כולל hash טקסט, גרסת קונטקסט ונמענים, גרסת חבילת כללים וגרסת מודל. שינוי בכל אחד מהם מבטל תוצאות תלויות.
9. **כשל מפורש:** timeout, שגיאת רשת או שגיאת ולידציה מחזירים `not_checked`. שגיאה לעולם אינה ״לא זוהה חשש״, ואין תוצאה אוטומטית של ״מותר״.

## רכיבים

```text
Adapter (WhatsApp/Gmail/Chat)
  -> MessageEnvelope { id, revision, direction, authorRef, audienceSnapshot, forwarded, text }
  -> LocalGate (סינון מקומי זול; מעבר שלו אינו הוכחת היעדר חשש)
  -> Extractor (פלט מובנה מאומת סכמה + ראיות + directAssessment אופציונלי;
       כולל הערכת משמעות לפי U-06: mayBeUnderstoodAsDisparagement,
       interpretationUncertain, mechanism, evidenceExcerpt, identifiable, confidence)
  -> FactStore (עובדות מאושרות/מוצעות/שנויות במחלוקת, scope ותוקף)
  -> RuleEngine (הערכה תלת־ערכית של חבילת כללים ב־JSON)
  -> QuestionPlanner (בחירת שאלה בתקציב)
  -> EvaluationResult { findings, draftObservations, needsClarification,
                        questions, limitations, disagreement, versions, cacheKey }
  -> UI (חלונית: חשש/מידע חסר/מקור/ניסוח חלופי כהצעת עריכה)
```

## חבילת כללים (Rule Pack)

קובצי JSON, גרסה אחת קנונית לכל כלל. שדות חובה: `id`, `version`, `domain`, `titleHe`,
`reviewStatus`, `applicability`, `conditions`, `outcome`.
שדות נוספים: `exceptions`, `requiredFacts`, `source`, `reviewer`, `fixtures`.

- ביטויי תנאי הם JSON בלבד (ללא קוד): `eq`, `in`, `exists`, `missing`, `gte`, `and`, `or`, `not`.
- `approved` בלי `source` תקין הוא שגיאת ולידציה של החבילה.
- כלל מאושר חייב fixtures וסקירה מתועדת (ראו [03-rules](03-rules.md)).
- עדכון כללים עתידי: חבילה חתומה עם גרסה; כל ממצא מציג `ruleId`, גרסת כלל, גרסת חבילה וסטטוס סקירה.

## קטלוג עובדות

כל עובדה שאפשר לשאול עליה מוגדרת פעם אחת בקטלוג: `id`, `questionHe`, `priority`,
`sensitivity` (`low`/`medium`/`high`), `persistent`, `confirmedByUserOnly`.
שאלות של כללים נגזרות מהקטלוג, לא מנוסחות בנפרד בכל כלל.

## שלבי אתרים

- **E1 — יוצאות:** סימון/כפתור ליד תיבת ההקלדה ויירוט שליחה רק אם הוכח אמין באתר בפועל.
- **E2 — נכנסות:** הסתרה לפני הצגה (דרישת U-03) היא שלב נפרד וקשה יותר; `IN-01` מנוסח כיעד מדיד עם מדיניות נפילה מפורשת, לא כהבטחה מוחלטת.
- המסלול המשפטי מחזיר מידע ואזהרה בלבד, לעולם לא ״יש הגנה״.
- למייל: `audienceSnapshot` מפורש (To/CC/BCC/נושא) כבר במודל ההודעה, לא רק ״קבוצה״.
- הודעות מועברות נושאות `forwarded` (ראו RES-002).

## מדדי שירות מוצעים (לבדיקה באבטיפוס)

סינון מקומי בעשרות מילישניות; timeout מפורש לקריאת מודל; מדידת p50/p95,
שיעור `not_checked`, עלות לבדיקה ושיעור התראות שווא על סט מתויג. ספי קבלה ייקבעו מהמדידות.

## מה כבר ממומש

ליבת מנוע ב־`engine/` (TypeScript, ללא תלות ב־DOM או בספק AI):
הערכת ביטויים תלת־ערכית, FactStore עם מדיניות מוצא, מתכנן שאלות בתקציב,
ולידציית חבילות, מפתח מטמון, וחבילות כללי **ניתוב־טיוטה** לתרחיש השיעור
ולשכבת המשמעות (`engine/src/meaning.ts`: `buildMeaningFacts` + `MEANING_ROUTING_PACK`).
בדיקות: `engine/test/`. הרצה: `npm --prefix engine test`.

## מה אינו ממומש ואינו מאושר

כללים הלכתיים/משפטיים מאושרים, אחסון מוצפן, חיבור חי לאתרים
(scraping/DOM אמיתי), והחלטות המוצר הפתוחות ב־06.
ה־Extractor ומתאמי השלד עם fixtures מומשו — ראו [09-extractor-connectors](09-extractor-connectors.md).
